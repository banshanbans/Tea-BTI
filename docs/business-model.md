# Tea-BTI 商业模型与验证路线

> 文档状态：商业策略基线，不代表当前版本已经实现交易、履约或 B 端后台。  
> 产品主张：**Tea-BTI 不是卖 AI 功能，也不是先做一个茶叶商城；它把原叶茶的第一次交易单位，从“一盒陌生的茶”变成“一次愿意开始的三杯体验”。**

## 1. 商业故事

年轻用户不是完全不想喝原叶茶，而是不知道第一杯该选什么、怎么泡、喝到的味道该怎么表达。传统茶商品通常从产区、工艺、等级和价格开始介绍，要求用户先懂茶再购买。

Tea-BTI 反过来设计这条路径：

> MBTI 低门槛破冰  
> → 推荐三个不同角色的茶样  
> → 用户为 First 3 实体探索盒付费  
> → Brew 帮他把茶泡出来  
> → Taste 帮他把感受说出来  
> → Tea Realm 让他理解味道从哪里来  
> → Passport 与 Tea-BTI 留下真实喝茶证据  
> → 下一杯推荐与正装导购

其中，MBTI 只负责降低第一次选择的心理成本，不进入 Taste Vector；推荐是否成立，最终由 Swipe、真实饮用和复购行为验证。

面向不同对象，统一表达为：

- 对用户：**不用先懂茶，先喝三杯。**
- 对茶企：**让一款茶不只从一盒商品开始，而从一次被年轻人真正喝懂的体验开始。**
- 对合作方 / 评委：**我们不是先建一个卖茶商城，而是在验证“被理解的一杯茶”能否提高尝试、完成和后续成交。**

## 2. 商业结构：产品、收入、渠道与资产分开

| 类型 | 组成 | 付费方 | 提供的价值 | 当前判断 |
|---|---|---|---|---|
| C 端切入产品 | First 3 探索盒 | 消费者，也可由品牌或活动方赞助 | 用低决策成本完成第一次真实尝饮 | 最优先商业实验 |
| B 端产品化服务 | Tea Fingerprint + 包装 QR + Brew + Taste + Tea Realm | 茶企、区域品牌、文旅运营方 | 把商品二维码升级为可交互、可持续的消费体验 | 近期最可行的 B 端收入 |
| B 端软件能力 | Tea Experience OS | 有多个 SKU 或持续运营需求的合作方 | 标准化管理茶事实、体验内容、用户反馈和聚合指标 | 验证重复交付后再 SaaS 化 |
| 成交验证 | 正装导购、合作商履约、佣金 | 茶企或渠道方 | 证明推荐不止产生互动，还能产生真实交易 | 可早期验证，但不自建商城 |
| 线下渠道 | Tea Station | 景区、茶博会、博物馆、酒店、茶空间 | 在真实场景完成扫码、试喝、记录与导购 | 是获客和展示渠道，不是独立平台模式 |
| 长期数据产品 | Consumer Taste Insights | 茶企、区域品牌、研究与渠道合作方 | 提供匿名聚合的年轻消费者口味洞察 | 数据成熟前不作为收入承诺 |
| 长期交易基础设施 | 自营商城、订单、支付、库存和售后 | 消费者与入驻商家 | 平台内完成完整交易 | 全产品最低开发优先级 |

Tea Realm 不是单独的收费模式。它首先是提高记忆、完成和文化理解的体验组件，其次才是 B 端方案中的差异化能力。《雾里一芽》应先成为可验证样板，再抽象为可复用引擎。

## 3. First 3：最小可收费验证

### 3.1 产品定义

First 3 由三款角色明确、风味差异足够大的贵州原叶茶组成：

1. `mirror`：最像用户当前表达的一杯；
2. `surprise`：可能带来惊喜的一杯；
3. `contrast`：与当前偏好有反差、但值得尝试的一杯。

每款以一次标准冲泡为单位。试点可默认采用 3g 茶样，但最终净含量必须依据茶品冲泡指南、合作方生产条件和标签要求确认，不能为了统一规格牺牲真实饮用效果。

每份茶样通过同一 `teaId + batchId` 关联：

- 经审核的茶事实与批次信息；
- Brew 冲泡指南；
- Taste 感官允许列表；
- 对应 Tea Realm 或文化片段；
- Passport 收集结果；
- 正装导购去向。

### 3.2 验证方式

首批只做小规模、可追踪的付费试点。允许使用外部收款、合作方订单页或人工登记完成支付和履约，不为试点开发商城。

First 3 要回答的不是 DAU，也不是 Swipe 次数，而是：

> **推荐三杯之后，用户愿不愿意付钱真正喝？收到以后，是否真的把茶泡了、喝了并留下反馈？**

### 3.3 单位经济

首批试点必须记录完整的单盒贡献毛利：

> 售价  
> − 茶叶与损耗  
> − 合规分装、包装与品控  
> − 仓储、物流与售后  
> − 支付通道费用  
> − 单次 AI 与短信等可变成本  
> − 可归因获客成本  
> = 单盒贡献毛利

茶叶克重小不等于毛利天然高。早期可以把 First 3 作为有补贴上限的获客产品，但必须明确每新增一位完成三杯体验的用户实际需要补贴多少。

## 4. 商业验证优先级与开发优先级

“验证正装成交”与“开发商城”是两件事，必须分开排序。

### 阶段 A｜先证明体验闭环

- 完成 Discover → Brew → Taste → Tea Realm → Passport → Tea-BTI；
- 用《雾里一芽》验证文化体验是否提高完成和记忆；
- 确保 MBTI 只参与破冰，真实行为负责推荐。

### 阶段 B｜证明 First 3 的付费与完成

- 使用小批量、合规生产的探索盒；
- 用外部支付或合作方履约，不建设订单中心；
- 同时观察购买、激活、泡饮、反馈和正装意向，而不是只看付款。

### 阶段 C｜证明 B 端愿意为效果付费

- 向少量合作方交付 `Tea Fingerprint + QR + Brew + Taste + Realm` 试点；
- 采用一次性建档 / 上线费，加年度使用或运营服务费；
- 把高度定制的拍摄、事实考证和专属 Tea Realm 单独计为项目费用，避免吞噬软件毛利。

### 阶段 D｜重复交付后产品化 Tea Experience OS

只有当多个合作方能共享同一内容模型、交互引擎和上线流程时，才把项目服务升级为按 SKU / 年度收费的软件产品。

### 阶段 E｜最后评估交易基础设施和数据产品

- 正装成交可继续使用品牌官方链接、导购码、联盟或合作商履约；
- 只有当平台内交易明显优于外部导购，且供应链、售后和商家治理可控时，才评估商城、订单和支付；
- Taste Insights 必须在样本量、代表性、授权、匿名化和客户需求都成立后再商业化。

Tea Station 不单独占用一条产品路线。出现有预算、有茶样、有场地的合作机会时，将其作为 First 3 和 B 端方案的线下验证渠道。

## 5. 核心指标与阶段闸门

| 要验证的问题 | 核心指标 | 通过后才能做什么 |
|---|---|---|
| 用户是否愿意开始 | 三杯结果查看率、First 3 付费转化 | 扩大探索盒测试 |
| 用户是否真正喝完 | 到货激活率、至少两杯完成率、Taste 反馈率 | 讨论 Next 3 / Deep 3 |
| 推荐是否有交易价值 | 正装点击、可归因订单、真实饮用后的喜欢率 | 扩大导购和品牌合作 |
| Tea Realm 是否创造价值 | 进入率、完成率、真实照片 Reveal 与标本收集、对后续行为的提升 | 抽象更多 Tea Realm 模板 |
| B 端是否获得明确回报 | 扫码激活、体验完成、留资 / 导购转化、单 SKU 交付成本 | 产品化 Tea Experience OS |
| 数据是否足够可靠 | 批次覆盖、有效反馈量、缺失率、重复饮用一致性、样本偏差 | 试做匿名聚合 Insights |

每轮试点开始前应写明目标值、样本范围、投入上限和停止条件，避免实验结束后再选择对自己有利的指标。

## 6. Tea Experience OS 的合理形态

Tea Experience OS 的核心不是“给每家茶企做一个 AI 页面”，而是把一款茶的可靠资料结构化为可复用体验。

### 6.1 Tea Fingerprint

每款茶至少包含：

- 茶品、产区、品类与批次；
- 原料和制作工艺；
- 经审核的专家感官描述；
- 分场景冲泡指南；
- 九维感官向量与允许使用的 Taste 标签；
- 干茶、茶汤、产区和关键工艺的真实锚点；
- 文化事实、来源、使用权和证据状态；
- 可进入的 Brew、Taste、Realm、Passport 与导购配置。

LLM 可以翻译表达、组织对话和归一化用户语言，但不能补造茶事实。

### 6.2 收费结构

合理的早期收费不是单一订阅价，而是：

- 建档与上线费：事实整理、素材审核、Tea Fingerprint 配置；
- 年度许可 / 运营费：QR 入口、体验托管、基础分析与版本维护；
- 可变服务费：新增 SKU、专属内容、拍摄、复杂 Tea Realm 和现场活动；
- 可选成交佣金：仅对可归因、由合作协议确认的交易收取。

这样可以防止把高成本定制项目伪装成高毛利 SaaS。

## 7. Taste Graph 与 Insights 边界

Taste Graph 首先服务于更好的用户推荐和体验恢复，不是当前即可出售的数据产品。

长期输出只允许是匿名聚合结论，例如：

- 哪类茶更容易成为年轻用户的第一杯；
- 专业茶语与用户自然表达之间的对应关系；
- 某个批次或场景下的泡饮完成与真实喜欢；
- 不同茶之间的共同喜欢关系。

必须同时满足：

- 获得与用途匹配的用户授权；
- 不出售个人画像、原始语音或可回溯到个人的记录；
- 区分批次差异、冲泡上下文和自述偏差；
- 对外数据达到不可识别且不可复原的匿名化要求；
- 对样本量、覆盖范围和代表性作明确说明。

现阶段应将其称为“数据与内容飞轮”，而不是已经形成的网络效应。只有新增用户和新增茶品能够持续、可测量地改善推荐、完成或成交时，才可以进一步主张数据壁垒。

## 8. 商业与合规护栏

- 不以广告作为核心收入；
- 不强制自动订阅探索盒；
- 不把 Tea-BTI 结果本身设为付费墙；
- 不销售个人用户数据或可重新识别的画像；
- 不让赞助、佣金或品牌预算改变推荐排序而不披露；
- 不自行进行无资质茶叶分装，优先由具备对应生产 / 分装条件的合作方完成；
- 二维码体验不能替代预包装食品实体标签中的强制信息；
- 数字标签、产品事实和溯源信息必须真实、准确、可追溯；
- 不用生成式内容承担茶形、茶汤、工艺或产区事实证明；
- 不在当前 MVP 开发商城、订单、支付、库存、退款或商家结算。

## 9. 当前决策

1. 当前版本继续优先完成产品体验闭环和《雾里一芽》；
2. First 3 是最优先的商业验证，不是当前商城开发需求；
3. 正装成交先通过外部导购和合作方履约验证；
4. B 端先卖可量化效果的产品化试点，再把重复能力升级为 Tea Experience OS；
5. Tea Station 只作为机会型渠道；
6. Taste Insights 与自营商城均为远期能力，其中商城、订单与支付保持全产品最低开发优先级。
