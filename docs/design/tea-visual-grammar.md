# Tea-BTI Tea Visual Grammar

> 版本：v0.2
> 状态：Hackathon Demo 设计基线  
> 适用范围：MBTI 三杯、八茶 Swipe、选择反馈、茶详情、Tea Realm、Tea Passport、Tea-BTI 与分享资产

---

## 1. 目的

Tea Visual Grammar 不是一套海报滤镜，而是Tea-BTI 的风味翻译系统。

它要在用户看见茶名的同时，用稳定的立体身份图与克制的情绪转译回答：

> 这杯茶喝起来，可能像什么？

它服务于产品原则：

> 先认识这杯茶，再用行为慢慢懂自己的口味。

详细规则只在本文维护。PRD、技术架构和前端生成 Prompt 只保留各自需要的摘要，并引用本文，避免多份规则逐渐漂移。

---

## 2. 系统定位

### 2.1 它是什么

- 一套跨茶品可复用、但不会让每张卡长得一样的视觉语法；
- 一套将 Tea Profile 转换为摄影选择、结构色、抽象形和环境暗示的规则；
- 一套同时约束立体展示、实拍详情和文化内容的视觉角色分工；
- 一套可以被设计师、前端、图像模型和内容团队共同执行的规格。

### 2.2 它不是什么

- 不是传统茶叶商品摄影模板；
- 不是为每杯茶套同一种撕纸、颗粒或复古纸刊效果；
- 不是用任意自然意象包装未经证实的香气与产地事实；
- 不是把外部 Visual Skill 复制进产品后的生产依赖；
- 不是用视觉暗示替代可靠的茶叶资料。

---

## 3. 五条核心原则

### 3.1 真茶为锚

每款茶必须同时具备一张立体身份图和一张对应实拍图。立体图负责跨页面识别与情绪表达，实拍图在详情页负责真实茶叶或饮茶体验的视觉锚点。

立体图不能冒充纪实照片；实拍图也不能替代经核验的产地、工艺或品质证据。

### 3.2 直接建立身份

MBTI、Swipe、选择反馈、推荐、护照和个人主页直接显示茶名，并始终使用对应的 `presentation` 立体图。茶详情切换为 `detail` 实拍图，同时补全产地、茶类、代表特点、香气滋味、性格关键词、冲泡建议和资料依据。

发现卡仍不显示品牌、商品等级、价格或内部九维向量，避免把识别式探索误做成商品货架或检测报告。

### 3.3 转译，不装饰

每一个结构色、抽象形和环境暗示都必须有来源：

- 来自已核验的 Tea Profile 感官维度；
- 来自真实摄影中的空间、颜色或形状；
- 或明确标记为不承担客观事实的体验隐喻。

如果移除一个视觉元素不影响风味感受、阅读路径或卡片区分度，它大概率只是装饰，应当删除。

### 3.4 一杯茶，一个视觉命题

每张卡只表达一个主感受，例如：

- 清晨薄雾里的轻与鲜；
- 暖色茶汤里的甜与圆润；
- 深色叶底里的厚与绵长。

不要在一张卡里同时表现山、花、果、火、雨、人物和多种工艺。

### 3.5 真实来源与使用权同等重要

每个进入产品的摄影或生成资产都必须记录来源和使用权状态。来源不明、权利不明或只能个人使用的素材，不进入正式生产资产库。

## 4. 首页卡片的视觉公式

八茶 Swipe 卡片采用：

> 一茶一幅完整立体身份图 + 统一宣纸色页面骨架 + 最少量结构化文字

立体图按原始约 9:16 构图使用 `object-fit: contain`，页面背景取与图内宣纸相近的暖米白色，不能为了填满卡片而裁掉图内茶名。页面层不再为同一张图叠加第二套海报滤镜、额外产地插画或无来源装饰。

### 4.1 固定层与变化层

| 层级 | 固定规则 | 可变化内容 |
| --- | --- | --- |
| 产品骨架 | 卡片比例、文字层级、按钮位置、可读性 | 不随茶变化 |
| 身份图 | 必须完整显示，不裁掉图内茶名 | 八张用户提供的立体设计图 |
| 结构色 | 每卡仅一个，承担视觉重心 | 由感官维度或真实素材提取 |
| 抽象形 | 每卡仅一个主语法 | 山脊、层线、圆块、不规则叶形等 |
| 环境暗示 | 只表达一个时刻或气氛 | 晨雾、春日、木桌、湿润森林等 |
| 纸面质感 | 轻、局部、不能压过内容 | 可在文化页增强，首页应克制 |

## 5. 双视觉角色与使用边界

| 素材角色 | 使用页面 | 显示规则 | 权利边界 |
| --- | --- | --- | --- |
| `presentation` | MBTI、Swipe、选择反馈、推荐、护照、个人主页 | 完整 `contain`，匹配宣纸背景 | `demo_only`，公开或商用前确认权利 |
| `detail` | 茶叶详情 | 逐图 `object-position`，允许响应式裁切 | `unknown`，仅非商业演示与设计参考 |
| `realm` | 都匀毛尖《雾里一芽》 | 遵循既有场景与真实性标注 | 逐项按清单记录 |
| `legacy` | 历史已打开卡片 | 保留路径与 ID，不进入当前 Feed | 维持原有登记 |

详情实拍图的页面来源与事实资料来源必须分开显示。去除水印不改变版权状态；原件、版本化编辑母版、编辑范围、尺寸和哈希都必须保留。

## 6. 三个转译变量

### 6.1 结构色

结构色不是角落里的装饰色块，而要承担至少一个功能：

- 建立卡片的视觉重心；
- 引导从文案到真实茶的观看路径；
- 连接真实摄影与抽象形；
- 区分不同风味区域。

结构色可以来自真实素材，也可以来自经核验的感官维度。不得用颜色暗示未经证实的原料、香气、工艺或功效。

### 6.2 抽象形

每张卡只选择一种主形态语法：

- 山脊线：轻、清、方向明确；
- 层叠横线：层次、茶园、生长节奏；
- 圆润色块：甜、暖、包裹感；
- 不规则叶形：厚、自然、原生感；
- 稀疏点状或短线：香气上扬、轻微跳跃感。

抽象形需要在缩略尺寸下仍然清楚。复杂叶脉、密集纹样和装饰性花纹应被压缩或移除。

### 6.3 环境暗示

环境暗示表达“喝这杯茶时像处在什么时刻”，例如晨雾、春日下午或傍晚木桌。

它属于体验隐喻，不等同于茶的真实产地、采摘时间或官方风味结论。涉及客观地点与工艺时，必须使用已核验资料，并移到 Reveal 或详情内容中。

## 7. 页面级分工

### 7.1 八茶 Swipe

- 目标：0.5 秒建立茶名与立体身份图的关系；
- 主体：完整 `presentation` 资产；
- 首态文字：茶名、茶类、产区、三项性格关键词和一句感受型短标题；
- 延后信息：代表特点、香气滋味、冲泡参数、证据链接留到详情；
- 布局：立体图占据主要视口并完整 `contain`，叠加轻量进度；
- 禁止：品牌、价格、商品等级和内部推荐向量。

### 7.2 选择反馈

- 保持同一视觉命题，不重新换一张无关图片；
- 真实锚点可从局部扩展到完整茶叶或茶汤；
- 茶名始终可见，反馈层确认用户刚刚选择的茶；
- 用一句话连接性格关键词与当下探索，但只使用“可能、也许、此刻”等非确定性措辞。

### 7.3 茶详情

- 首屏仍以真实茶为主，不做传统商品详情；
- “泡茶 → 品茶 → 茶境 → 护照”使用 Journey Rail 展示，只有服务端推荐的下一步保持最高操作层级；
- 其他阶段放入弱化的“自由探索”，Tea Realm 始终可进入；
- 视觉转译减弱，让冲泡资料、官方描述和个人记录接管信息层级。

### 7.4 产地故事

采用“真实产地摄影 + 从该照片关系中提炼的抽象记忆面板”。抽象内容必须能回溯到原照片的空间、色彩或结构，不能把照片中不存在的兰花、栗子、云雾或人物凭空加入真实产地叙事。

### 7.5 Tea Realm

允许更强的像素与纸面表达，但仍继承对应茶的结构色、主形态和环境气氛。Tea Realm 是同一视觉身份的世界化扩展，不是另一套随机美术风格。

### 7.6 Tea Passport 与 Tea-BTI

- Passport 保存真实喝过的证据，优先显示真实茶缩略图；
- Tea-BTI 汇总用户跨茶品的偏好，不直接复制任何单款茶的完整卡面；
- 分享卡可以增强编辑感，但不能牺牲人格轴、证据茶品和状态文案的可读性。

## 8. 基础视觉令牌

以下为 Demo 起始值，不是不可调整的品牌终稿。

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| Warm Paper | #F6F2E8 | 页面与卡片主背景 |
| Ink Green | #183B2B | 主文字与深色 UI |
| Leaf Green | #79A85B | 轻互动强调，不作为每杯茶的固定结构色 |
| Tea Amber | #C78B45 | 茶汤与温暖状态辅助色 |
| Mist | #DCE8DD | 安静背景与薄雾层 |
| Charcoal | #2E312D | 次级深色文字 |

字体角色：

- 展示文字：现代宋体或克制的中文 Serif，用于茶名和情绪标题；
- UI 与正文：清晰的中文 Sans，用于按钮、标签和说明；
- 不把复古打字机体作为全产品固定字体；
- Swipe 卡片主文案最多两级，不叠加海报式微文字系统。

质感规则：

- 首页只允许极轻颗粒或纤维感；
- 撕纸边界只能作为少数文化内容或分享资产的强调手段；
- 不使用厚重阴影、卷边纸张、拼贴胶带和 Scrapbook 装饰；
- 所有质感在小屏缩略尺寸下都必须退居内容之后。

## 9. 八茶活动映射

下表定义详情实拍图的初始焦点；立体图一律完整 `contain`。

| 茶品 | 详情 `object-position` | 性格关键词 |
| --- | --- | --- |
| 都匀毛尖 | `50% 50%` | 灵动、敏锐、清醒 |
| 湄潭翠芽 | `50% 48%` | 克制、细致、有秩序 |
| 绿宝石茶 | `50% 48%` | 沉稳、凝聚、有韧性 |
| 普安红 | `66% 50%` | 温暖、深沉、有包容力 |
| 凤冈锌硒茶 | `50% 55%` | 自然、平衡、可靠 |
| 遵义红 | `58% 50%` | 热烈、坚定、有行动力 |
| 雷山银球茶 | `50% 56%` | 内敛、慢热、层层展开 |
| 梵净山抹茶 | `50% 50%` | 专注、鲜明、充满能量 |

同一茶品在 MBTI、Swipe、选择反馈、推荐、护照和个人主页使用同一 `presentation` 资产；详情使用对应 `detail` 资产。都匀毛尖 Tea Realm 继续继承其 Visual Profile。

## 10. 动效规则

### Swipe

- 动效跟随手势，不让纹理或背景独立漂移；
- 右滑时 Heart 随距离放大、填充并出现柔光，左滑时 X 放大并增强对比，反向图标同步退场；
- 第二张卡随拖动从下方上移并恢复尺寸，第三张卡同步补位；
- 点击按钮必须复用手势的飞卡动画与提交逻辑；
- 未过阈值整组回弹，提交失败恢复原卡并保留重试入口；
- 卡片回弹后必须恢复清晰的文字与视觉层级。

### Reveal

- 情绪文案不是瞬间消失，而是退到次级；
- 茶名从真实锚点附近出现，建立“原来是它”的联系；
- 专业标签按顺序进入，不做粒子爆炸或强烈庆祝动画。

### 跨页面

结构色与主形态可以作为 Shared Element 延续到详情或 Tea Realm。转场要让用户感到同一杯茶被逐步理解，而不是跳到另一张海报。

## 11. Visual Profile 数据契约

每款茶的视觉配置至少包含：

    visual_profile:
      primary_anchor_asset_id: string
      anchor_types: (stylized_identity | tea_liquor | infusion | wet_leaf | dry_leaf | brewing_action)[]
      structure_color: string
      structure_color_basis: string
      abstract_form: string
      abstract_form_basis: string
      atmosphere_cue: string
      atmosphere_is_metaphor: boolean
      evidence_refs: string[]
      overlay:
        bottom_percent: number
        left_percent: number
        width_percent: number
        height_percent: number
        opacity: number
        atmosphere_opacity: number

    visual_asset:
      role: presentation | detail | realm
      active: boolean
      source_kind: user_provided | third_party_photo | ai_generated | self_shot | licensed_photo
      authenticity_state: stylized_demo | reference | synthetic_demo | documentary
      rights_state: owned | licensed | demo_only | unknown
      rights_note: string
      source_url: string
      original_path: string
      master_path: string
      media_path: string
      crop_strategy: string
      original_sha256: string
      master_sha256: string
      sha256: string
      edit_chain: EditStep[]

运行时不应让 LLM 自由生成 Visual Profile。Demo 使用人工审核的静态配置；后续如引入辅助生成，也必须经过内容、视觉和权利检查后才能发布。

首批实现以 `assets/tea-visuals/manifest.json` 为运行与评审的单一事实来源，并用同目录的 JSON Schema 校验。

## 12. 资产流程

    已核验 Tea Profile
      → 摄影与裁切简报
      → 素材来源和权利登记
      → Visual Profile 配置
      → 生成或制作基础视觉资产
      → 角色与完整构图检查
      → 风味可追溯检查
      → 小屏可读性检查
      → 导出并写入资产清单

Hackathon 现场原则：

- Swipe 卡片使用提前制作并本地缓存的静态资产；
- 不依赖现场图像生成；
- 同一资产至少导出移动端主尺寸与高密度版本；
- 原图、裁切图和最终资产使用稳定 ID 关联；
- 素材权利不清晰时，用自摄、明确授权素材或项目自有生成方案替换。

## 13. 质量门槛

每张核心视觉必须通过：

1. 0.5 秒测试：不读文字时能否感到一个明确气质；
2. 真实茶测试：是否仍然看得出这是现实饮茶体验；
3. 身份完整测试：茶名是否直接可见、立体图是否没有被裁切；
4. 可追溯测试：结构色、抽象形和环境暗示是否有依据；
5. 单命题测试：是否只表达一个主感受；
6. 模板疲劳测试：连续看三张是否只是换颜色和照片；
7. 小屏测试：在 390px 宽度下文案、标签和真实锚点是否清楚；
8. 对比度测试：文字与操作是否满足移动端可读性；
9. 动效测试：选择反馈后是否仍能理解刚刚操作的是同一款茶；
10. 权利测试：素材来源与使用范围是否明确。

## 14. 外部视觉研究与许可边界

本规范参考了以下公开项目的设计思路：

- Gathered Scenes Zine：真景为锚、抽象扩场、结构色与留白；
- Photo Abstract Editorial：保留原始摄影，并让抽象关系严格来自源照片。

参考地址：

- https://github.com/Zeejay0/gathered-scenes-zine-skill
- https://github.com/ZzzLc0405/photo-abstract-editorial

这两个项目当前都限制商业使用。项目执行规则：

- 不把其 Skill、Prompt 或工作流文件复制进Tea-BTI 仓库；
- 不把它们作为产品运行时依赖；
- 未获得明确许可前，不直接使用其 Skill 产出商业交付资产；
- 只吸收一般设计原则，并用本文重新定义Tea-BTI 自己的系统；
- 如需直接使用，先完成书面授权确认并记录许可范围。

## 15. 48 小时 Demo 交付范围

必须完成：

- 八款 Demo 茶的 Visual Profile；
- 八张完整立体卡片与八张详情实拍图；
- 都匀毛尖从立体展示 → 选择反馈 → 实拍详情 → Tea Realm 的完整视觉继承；
- 两张只处理指定水印区域的版本化实拍母版；
- Tea Passport 缩略图与 Tea-BTI 证据茶品的统一资产；
- 资产来源、尺寸、哈希、编辑链与权利状态清单。

可以延后：

- 八款以外的贵州茶视觉映射；
- 自动视觉配置生成；
- 运行时图像生成；
- 多套分享海报主题；
- 正式品牌字体与商业图库采购。
