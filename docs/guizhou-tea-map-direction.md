# Tea-BTI 完整贵州地图方向：贵州茶脉探索图

> 文档状态：产品方向 v0.1  
> 当前状态：尚未开发，不属于现有 MVP 已交付能力  
> 关联模块：Tea Realm、Tea Passport、Tea Profile、Recommendation  
> 核心判断：地图是个人茶探索的空间视图，不是行政百科、旅游导览或经营游戏。

## 1. 决策摘要

完整贵州地图采用：

> **九市州地理底板 + 茶脉路线 + 个人茶足迹与数字标本**

九个市州提供稳定的地理结构；经过审核的茶品和产区形成“茶脉”；用户的 Reveal、收藏、冲泡、品饮和 Tea Realm 完成记录决定地图如何呈现个人探索进度。

地图只回答三个问题：

1. 我在贵州认识过哪些茶；
2. 我真正泡过、喝过哪些茶；
3. 我在哪些地方完成过 Tea Realm，并带回了什么数字标本。

地图不负责判断用户是否“懂茶”，不设置付费解锁，不以打卡数量替代真实体验，也不向 Taste Vector 或 Tea-BTI 写入信号。

## 2. 为什么不直接做行政区涂色

纯行政地图容易变成文旅官网，纯标本星图又会失去贵州地理认知。推荐将三种表达分层：

| 层级 | 作用 | 表达 |
|---|---|---|
| 九市州底板 | 建立完整贵州空间认知 | 真实边界、轻量名称、无夸张地貌 |
| 茶脉路线 | 解释不同茶之间的地域与工艺联系 | 茶品节点、产区连接、下一处探索 |
| 个人足迹 | 呈现用户自己的真实经历 | 遇见、泡过、品过、Realm、标本 |

最终体验不是“把九块区域全部刷亮”，而是：

> **喝过的茶，会慢慢长成你的贵州。**

## 3. 产品边界

### 3.1 这是

- Tea Passport 的空间视图；
- Tea Realm 的章节入口和完成回流页面；
- 发现“下一杯”的探索界面；
- 后续 Tea Profile `TEA_MAP` Block 的数据来源。

### 3.2 这不是

- 全量贵州茶数字博物馆；
- 开放世界或农场经营游戏；
- 行政区知识考试；
- 景区导航或实时位置地图；
- 通过签到、积分或购买强制解锁的关卡；
- 用生成式内容编造产地、民族文化或工艺事实的页面。

所有区域始终可以浏览。“待认识”只代表用户还没有留下行为证据，不代表禁止进入。

## 4. 地图状态模型

地图状态应从已有行为记录派生，首版不再维护一套可被客户端直接修改的“点亮进度”。

| 状态 | 主要证据 | 地图表现 | 用户文案 |
|---|---|---|---|
| `available` | 无个人行为 | 保留区域轮廓与审核后的基础茶点 | 待认识 |
| `encountered` | 喜欢/收藏后 Reveal 茶品 | 茶点出现微弱光环，不点亮整区 | 遇见过这杯 |
| `experienced` | Brew、Taste、Drink Feedback 或 Passport 记录 | 茶点转为实色，形成个人脚印 | 泡过 / 品过 |
| `realmCompleted` | Tea Realm 完成记录 | 对应区域形成柔和亮区，并展示标本 | 深入走过 |

同一区域可以包含多款茶，区域状态按最高真实证据展示，但必须保留每款茶自己的状态。例如用户品过遵义红、只收藏湄潭翠芽时，不能把两款茶都显示为“品过”。

### 4.1 不变量

- 打开地图、点击区域、浏览茶点不改变 Taste Vector；
- 完成 Tea Realm 只改变 Realm、Passport、地图和标本状态；
- 地图推荐“下一杯”仍调用茶品级推荐结果，不用地域刻板印象代替茶向量；
- MBTI 不参与地图点亮；
- 重复完成 Realm 不重复发放标本或累计区域完成数。

## 5. 九市州内容骨架

贵州省当前共有六个设区市、三个自治州，共九个地级政区。首版地图使用九市州作为稳定底板，不直接下钻全部 88 个县级政区。

以下县市来自贵州省公开的精制茶优势产区/加工集聚区，可作为内容建设索引；它们不自动等于产品中的代表茶、地理标志范围或 Tea Realm，正式上线前仍需逐项建立茶品资料与事实证据。

| 市州 | 可优先整理的茶区索引 | 首版产品状态建议 |
|---|---|---|
| 贵阳市 | 开阳 | 有地理底板，待补审核茶品 |
| 六盘水市 | 六枝 | 有地理底板，待补审核茶品 |
| 遵义市 | 湄潭、凤冈、正安、余庆 | 已有湄潭翠芽、遵义红，可首先形成双茶节点 |
| 安顺市 | 西秀 | 有地理底板，待补审核茶品 |
| 毕节市 | 金沙 | 有地理底板，待补审核茶品 |
| 铜仁市 | 石阡、印江、思南、江口 | 优先调研石阡苔茶、梵净山相关茶品 |
| 黔西南州 | 普安、晴隆 | 优先调研普安、晴隆相关茶品 |
| 黔东南州 | 黎平、雷山 | 优先调研雷山银球、黎平相关茶品 |
| 黔南州 | 都匀、贵定、瓮安 | 已有都匀毛尖和《雾里一芽》，作为首个点亮区域 |

首版数据不应为了“九区都有茶”而填入未经审核的品牌、产区或感官描述。地理结构可以完整，内容证据允许分阶段完善。

## 6. 核心界面

### 6.1 茶境首页 / 地图首屏

移动端 390×844 视口建议：

- 顶部：`贵州茶脉`、个人足迹摘要；
- 中部约 55%–65%：贵州地图与主要茶点；
- 底部抽屉：当前区域、已留下的证据和一个主行动；
- 底部导航继续属于现有 App Shell，不增加第四个一级入口。

示意层级：

```text
贵州茶脉
你已在 2 个茶区留下脚印

        [贵州九市州地图]
   ● 遵义 ───────── ● 黔南
    遇见 2 杯          完成茶境

黔南 · 你走得最深的一处
都匀毛尖｜品过｜白毫标本
[继续探索黔南]
```

### 6.2 区域抽屉

点击区域后只展示三类信息：

1. **我与这里**：遇见、收藏、泡过、品过、完成 Realm 的茶；
2. **这里的茶**：已经审核并可以进入产品流程的茶品；
3. **下一步**：查看茶详情、泡/品一杯、进入已有 Realm，或查看“章节筹备中”。

不要放入长篇区域介绍、泛化风味结论、景点列表或与喝茶主线无关的资讯流。

### 6.3 茶节点

茶节点至少区分：

- 茶名；
- 茶类；
- 用户证据状态；
- 是否存在 Tea Realm；
- 是否拥有数字标本。

节点视觉继承同一款茶的 Visual Profile，但在地图缩略态只使用结构色、形态符号和小尺寸真实锚点，避免把地图变成卡片墙。

### 6.4 完成 Tea Realm 后回流

Realm 完成后：

1. 收集标本；
2. 返回地图；
3. 对应区域从 `experienced` 过渡到 `realmCompleted`；
4. 展示“你从黔南带回一枚白毫标本”；
5. 提供“查看 Passport”或“认识相邻茶脉”，不强制继续。

## 7. “下一处探索”如何推荐

地图可以承接推荐结果，但不能自行发明地域人格。

允许：

> 你最近更常留下清鲜、轻盈的茶，这一杯可能值得去认识。

不允许：

> 你属于黔南型人格。  
> 黔南的茶都清鲜。  
> 你与遵义有 91% 匹配度。

候选仍按具体茶品的九维向量计算；地图只负责把推荐茶定位到相应区域，并解释用户为何从当前茶脉走向下一杯。

## 8. 视觉与事实边界

### 8.1 必须真实

- 贵州省及九市州的边界关系；
- 茶品与产区的对应关系；
- 地理标志或区域品牌的适用范围；
- 茶叶形态、茶汤、工艺和产区真实照片；
- 民族、历史和非遗内容的出处。

### 8.2 可以风格化或生成

- 雾层；
- 纸张、拓印或等高线质感；
- 非事实性的光晕、路径和过渡；
- 尚未探索区域的抽象氛围层。

生成素材不得承担行政边界、真实地貌、茶园位置或民族文化事实证明。地图几何数据、真实照片和图标资产都要登记来源、许可、真实性与证据状态。

### 8.3 动效与可访问性

- 区域点亮使用 0.6–1.2 秒柔和过渡，不使用爆炸式奖励；
- 支持 `prefers-reduced-motion`，关闭路径流动和雾层位移；
- 每个地图区域都必须有键盘焦点与可读标签；
- 同步提供九市州列表视图，确保无法操作地图的用户也能完成全部任务；
- 不依赖颜色单独表达状态，应结合图标、文字和描边变化。

## 9. 建议领域模型

以下是后续技术设计输入，不在本文直接冻结公共 API：

```ts
RegionDefinition {
  regionId: string
  name: string
  type: "city" | "autonomousPrefecture"
  geometryAssetId: string
  teaIds: string[]
  teaAreaReferences: string[]
  evidenceRefIds: string[]
}

TeaMapRegionSummary {
  regionId: string
  state: "available" | "encountered" | "experienced" | "realmCompleted"
  encounteredTeaIds: string[]
  brewedTeaIds: string[]
  tastedTeaIds: string[]
  completedRealmIds: string[]
  specimens: RealmSpecimen[]
  recommendedTeaId?: string
}
```

### 9.1 数据归属

| 内容 | 事实来源 |
|---|---|
| 九市州与地图几何 | 版本化 Region Definition 与合规地图数据 |
| 茶品节点 | 审核后的 Tea Catalog |
| 遇见状态 | Swipe Reveal / Save 记录 |
| 泡过、品过 | Passport、Brew、Drink Feedback |
| Realm 完成 | RealmProgress |
| 标本 | RealmSpecimen |
| 下一杯 | 当前 Recommendation Service |

地图服务以聚合查询为主，不复制茶事实，也不接受客户端直接提交“点亮某区域”。

## 10. Analytics

建议事件：

```text
tea_map_viewed
tea_map_region_opened
tea_map_tea_node_opened
tea_map_next_exploration_started
tea_map_realm_started
tea_map_passport_opened
```

记录 `regionId / teaId / realmId / source` 等结构化字段，不记录用户完整品饮原话。指标重点不是地图点击量，而是：

- 地图是否促进下一款茶详情访问；
- 是否提升 Brew / Taste 开始率；
- 是否促进 Realm 进入与完成；
- 完成 Realm 后是否回看 Passport；
- 用户是否形成跨区域的真实品饮记录。

## 11. 分阶段交付

### Phase 1｜地图骨架

- 九市州真实边界；
- 黔南、遵义、黔西南、黔东南与铜仁接入现有八款茶；
- `available / encountered / experienced / realmCompleted` 四态；
- 区域抽屉、键盘操作、列表降级；
- 《雾里一芽》完成后回流地图；
- 地图状态全部由现有数据派生。

### Phase 2｜九市州内容覆盖

- 按官方茶区索引完成九市州资料审核；
- 每个市州至少有一个可解释茶节点或明确的“资料筹备中”；
- 增加跨区域茶脉与“下一处探索”；
- 不要求每个区域立即拥有 Tea Realm。

### Phase 3｜多 Tea Realm 与 Profile

- 新增第二、第三个高质量 Tea Realm；
- 形成跨区域 Realm 路线；
- 在 Tea Profile 增加可隐藏的 `TEA_MAP` Block；
- 分享页只展示用户明确公开的区域足迹和标本。

## 12. Phase 1 验收条件

1. 九市州边界与名称可追溯，移动端无横向溢出；
2. 未探索区域也能进入，不出现惩罚式锁定；
3. 都匀毛尖、湄潭翠芽、遵义红映射到正确区域；
4. Reveal、Brew/Taste、Realm 完成分别产生正确状态，不互相冒充；
5. 地图交互前后 Taste Vector 与 Tea-BTI 四轴完全不变；
6. 《雾里一芽》重复完成不重复点亮或发放标本；
7. 减少动态效果、键盘和九市州列表都可以访问完整内容；
8. 生成素材不承担行政边界、真实产区或茶事实证明；
9. 区域抽屉不展示精确饮用时间、私密对话或未公开原话；
10. Chromium、WebKit 在 390×844 视口完成地图 → 茶详情 → Realm → 地图回流。

## 13. 当前事实债务与开放问题

- 获取可用于产品展示的贵州九市州地图几何数据及明确许可；
- 为九市州逐项确定代表茶，而不是仅按产业集聚县自动推导；
- 为茶品、区域品牌、地理标志保护范围建立独立证据；
- 确定第二个 Tea Realm 选题，使其在茶类、工艺和地域上与《雾里一芽》形成明显差异；
- 完成真实设备上的地图手势、区域触控面积与减少动态效果测试。
