# Tea-BTI PRD

> **一句话定位**：一个年轻人第一次进入原叶茶世界的发现界面。  
> **核心表达**：你不用先懂茶。刷几下，茶先开始懂你。  
> **传播 Hook**：你的 MBTI，会喝什么茶？先从三杯开始。  
> **推荐原则**：MBTI 负责破冰，刷茶负责懂你。  
> **产品闭环**：Discover → Brew → Taste → Explore → Remember → Evolve  
> **商业验证闭环**：Discover → First 3 → Brew → Taste → Tea Realm → Passport → Next Tea

---

## 1. 产品背景

年轻用户正在逐渐接近茶，但原叶茶的“发现界面”仍然高度依赖专业知识。

第一次接触原叶茶时，用户通常会直接遇到：

- 六大茶类；
- 产区、山场、树种；
- 工艺、等级；
- 嫩香、栗香、鲜爽、回甘、醇厚等专业感官描述；
- 大量商品参数和历史文化介绍。

这些信息并非错误，但它们默认用户已经进入了茶的语言体系。

Tea-BTI 希望解决的不是“教育年轻人爱茶”，而是：

> **让一个不懂茶的人，不需要先学习，也能找到第一杯真正想喝的原叶茶。**

产品先借用户熟悉的 MBTI 语言完成一次低门槛破冰，再用“刷”观察真实选择；随后通过 AI 陪伴帮助用户把茶泡出来、喝明白，最后通过互动文化体验、茶护照和 Tea-BTI 形成长期留存。

## 2. 核心 Product Insight

### 2.1 茶不缺信息，缺的是“第一次进入茶世界”的界面

传统路径：

> 先理解茶类 / 术语 / 工艺 → 再选择茶

Tea-BTI 路径：

> 先产生感觉 → 再认识这是什么茶 → 再逐渐理解专业语言

### 2.2 MBTI 只负责冷启动，真实行为负责推荐

Tea-BTI 可以把 MBTI 作为主传播入口，但不做 16 型人格测试，也不把人格类型解释成科学的饮茶结论。

用户只需直接选择自己已知的 MBTI；不知道或不想选择时，可以点击“先刷再说”。系统据此给出三款角色不同的贵州茶：

1. **最像你**：提供熟悉感；
2. **可能让你惊喜**：扩大探索边界；
3. **和你反差但值得试**：保留意外发现。

MBTI 只决定第一批候选茶的顺序、角色和解释文案，不直接写入 Taste Vector，不形成永久标签。用户开始刷茶后，真正进入推荐系统的信号来自：

- 喜欢；
- 跳过；
- 收藏；
- 真喝后的反馈。

这些行为逐渐形成用户的 **Taste Vector**，并覆盖冷启动假设。

### 2.3 AI 不应该作为“聊天框功能”出现，而应该分布在关键时刻

AI 在产品中的角色：

- 帮用户发现：根据 Swipe 动态调整 Feed；
- 帮用户泡茶：视觉理解 + 实时语音陪伴；
- 帮用户品茶：把用户的自然语言翻译成茶的专业语言；
- 帮用户理解自己：形成 Tea-BTI；
- 帮用户回忆：记住喝过什么、怎么描述、喜欢哪一泡；
- 帮用户继续发现：根据长期 Taste Vector 推荐下一杯。

### 2.4 MBTI 与 Tea-BTI 必须明确分层

| 层级 | MBTI 冷启动 | Tea-BTI 味觉人格 |
|---|---|---|
| 来源 | 用户自报 | Swipe、真喝、收藏、品饮语言 |
| 作用 | 破冰、传播、生成第一批三杯 | 记录长期味觉身份、支持分享与回顾 |
| 生命周期 | 首次进入时使用，可跳过、修改或删除 | 随行为逐步形成并持续变化 |
| 是否进入推荐核心 | 否，只选择第一批候选与顺序 | 底层仍由连续 Taste Vector 驱动 |
| 对外表达 | “可能和你合拍” | “这是你喝出来的偏好” |

禁止把两者合并成“某 MBTI 天生适合某款茶”的确定性结论。

## 3. 目标用户

### 3.1 核心用户

18–30 岁、对茶有一定兴趣但不是传统茶圈用户的人。

典型特征：

- 喝过奶茶、咖啡、新茶饮；
- 对原叶茶有兴趣，但不知道第一杯怎么选；
- 不熟悉专业茶语；
- 不愿意在使用产品前完成长问卷；
- 熟悉或愿意使用 MBTI 作为社交语言，但不一定认可其科学性；
- 愿意接受短视频、Swipe、游戏化、AI 陪伴等轻量交互；
- 有较强的收藏、人格表达和分享需求。

### 3.2 场景用户

#### A. 景区 / 文旅游客

在贵州景区、茶文化空间、文创店看到二维码：

> **“刷几杯，看看贵州哪杯茶会选中你。”**

目标：

发现茶 → 现场试喝 → 产生购买。

#### B. 茶叶购买用户

扫描茶叶包装二维码：

> **“第一次喝？我陪你泡。”**

目标：

购买 → 泡茶陪伴 → 品茶 → 文化体验 → 收藏 → 下一次推荐。

#### C. 线上自然用户

从社交分享、Tea-BTI 卡片、朋友推荐进入。

目标：

选择或跳过 MBTI → 看第一批三杯 → 继续刷茶 → 建立 Taste Vector → 找到想尝试的茶。

## 4. 产品目标

### 4.1 用户目标

1. 不懂茶也可以开始选茶；
2. 找到“我愿意真正喝一口”的第一杯；
3. 第一次泡原叶茶时不再无从下手；
4. 喝到味道以后能用自己的语言表达；
5. 在不被“上课”的情况下理解茶背后的地域、工艺与文化；
6. 逐渐形成自己的喝茶记录和味觉身份。

### 4.2 商业目标

对文旅 / 景区：

- 降低贵州茶的第一次认知门槛；
- 将游客从“路过茶产品”转化为“愿意试喝”；
- 提升文创店、茶空间的互动体验。

对茶商：

- 将包装二维码从防伪 / 商城入口升级为产品体验入口；
- 延长购买后的数字关系；
- 获得匿名聚合的真实偏好数据；
- 支持后续复购和跨茶品推荐。

对平台：

- 形成用户 Taste Vector；
- 形成 Tea ↔ User Preference 的 Taste Graph；
- 逐渐积累真实的年轻消费者原叶茶偏好数据。

### 4.3 MVP 漏斗指标

首轮验证不追求“MBTI 匹配准确率”，而关注它是否有效降低第一次开始的门槛：

| 阶段 | 核心事件 | 建议观察指标 |
|---|---|---|
| 破冰 | `mbti_selected` / `mbti_skipped` | 进入三杯推荐的完成率 |
| 第一批三杯 | `seed_tea_opened` / `seed_batch_continue` | 三杯查看率、继续刷茶率 |
| 行为学习 | `swipe_liked` / `swipe_skipped` | 首次 Swipe 率、5 次 Swipe 完成率 |
| 推荐验证 | `recommendation_opened` / `drink_intent_created` | 推荐进入详情率、想喝率 |
| 长期闭环 | `brew_started` / `taste_logged` / `passport_saved` | 陪泡、陪品与收藏转化 |
| 文化沉浸 | `realm_preview_opened` / `realm_started` / `realm_completed` | 茶境进入率、各幕完成率、标本收集率 |
| 身份沉淀 | `tea_profile_viewed` / `profile_block_edited` | Tea Profile 查看率、Block 编辑率 |
| 分享拉新 | `tea_profile_shared` / `public_profile_opened` / `profile_cta_started` | 分享率、公开页打开率、好友破冰转化 |

守护指标：用户即使跳过 MBTI，也必须能顺利进入刷茶；不同 MBTI 不能产生完全相同的角色顺序与解释文案。

### 4.4 商业故事与验证顺序

Tea-BTI 不是以售卖 AI 功能为核心，也不先建设茶叶商城。商业上的核心变化是：

> **把原叶茶的第一次交易单位，从“一盒陌生的茶”变成“一次愿意开始的三杯体验”。**

最小可收费产品是 **First 3 探索盒**：`mirror / surprise / contrast` 三款茶分别提供熟悉感、惊喜和反差。MBTI 只帮助用户开始，Swipe、真实饮用、Taste 反馈和后续成交负责验证推荐是否成立。

First 3 属于核心体验稳定后的第一项商业实验，不属于当前 48 小时 MVP 的生产、支付或履约范围；当前 MVP 只验证三杯推荐、`drink_intent_created` 和后续数字体验是否成立。

商业能力按性质分层：

| 层级 | 能力 | 当前定位 |
|---|---|---|
| C 端切入产品 | First 3 探索盒 | 最优先商业实验，验证用户是否愿意为三杯真实体验付费 |
| B 端产品化服务 | Tea Fingerprint + QR + Brew + Taste + Tea Realm | 近期可售卖试点，按建档、上线、年度运营和定制内容收费 |
| B 端软件能力 | Tea Experience OS | 多个合作方能够复用相同交付流程后再 SaaS 化 |
| 成交验证 | 正装外链、导购码、合作商履约或佣金 | 可早期验证推荐的交易价值，但不要求平台内交易 |
| 线下渠道 | Tea Station | 景区、茶博会和茶空间中的获客 / 验证渠道，不单独建设重运营业务 |
| 长期资产 | Taste Graph / Consumer Taste Insights | 先服务推荐；数据规模、授权和匿名化成熟后再考虑商业化 |
| 交易基础设施 | 自营商城、订单、支付、库存和售后 | 全产品最低开发优先级 |

商业验证顺序：

1. 先完成 Discover → Brew → Taste → Tea Realm → Passport → Tea-BTI 核心闭环；
2. 使用小批量、合规生产的 First 3 测试付费和真实泡饮，支付与履约可由外部渠道或合作方完成；
3. 使用官方链接、导购码或合作商订单验证正装成交，不开发商城；
4. 向少量茶企交付可量化效果的 Tea Experience QR 试点；
5. 在内容模型、交互引擎和上线流程被重复验证后，再产品化 Tea Experience OS；
6. Tea Station 只在有预算、茶样和场地的合作机会中作为线下渠道；
7. Taste Insights 与自营商城均留到远期。

First 3 的关键指标不是 DAU 或 Swipe 数量，而是付费转化、到货激活、真实泡饮完成、Taste 反馈、正装成交意向和单盒贡献毛利。完整商业模型、单位经济、B 端收费结构、数据与合规护栏见 [`business-model.md`](business-model.md)。

## 5. 非目标

48 小时 Demo 不做：

- 商城、订单与支付（全产品最低优先级；不进入当前 MVP 或紧接着的开发阶段，只在 Discover → Brew → Taste → Tea Realm → Passport → Tea-BTI 核心闭环稳定后再评估）；
- 社区 / 茶友广场；
- 复杂积分体系；
- 茶友排行榜；
- 16 型人格问卷；
- “某 MBTI 天生适合某款茶”的确定性或科学化声称；
- 用 MBTI 替代 Swipe、真喝反馈和 Taste Vector；
- “看茶汤颜色就判断茶好坏”的伪科学能力；
- 精确识别水温、克数等无法由普通摄像头可靠获得的数据；
- 全量贵州茶数字博物馆；
- 多款茶的完整 2.5D 游戏章节；
- 开放地图、农场经营、复杂关卡或重游戏成长系统；
- 使用无真实资料锚点的生成图像代替茶叶形态、工艺、茶汤或产地事实；
- 复杂机器学习训练。

# 6. 核心 User Journey

## Journey 0：MBTI 破冰

默认线上入口与景区传播入口首先展示：

> **你的 MBTI，会喝什么茶？**  
> 先从三杯开始。

用户在横向吸附式转盘中浏览 INFP / ENTP / ISTJ 等已知类型，不做题、不注册。中心卡展示四字母代码和一句原创气质描述，左右相邻卡部分露出；页面同时提供：

> **还没测过？先凭感觉开始。**

完成标准：最多两次点击进入第一批三杯，不出现人格报告、匹配百分比或科学测评措辞。

新用户、未完成破冰的用户以及 `fromProfile` 访问者，在 Bootstrap 成功后直接进入 MBTI，第一步可操作界面不再经过启动按钮。已完成破冰的回访用户展示约 `0.8s` 品牌过渡，随后自动恢复 Feed。MBTI 和三杯结果属于独立冷启动流程，不显示底部一级导航；Bootstrap 失败时留在同一外壳，提供自然语言重试。

## Journey 1：第一批三杯

系统一次给出三款“可能和你合拍”的贵州茶。三张卡必须承担不同探索角色，而不是把同一结论换三种说法：

1. **最像你**；
2. **可能让你惊喜**；
3. **和你反差但值得试**。

首批候选池使用全部八款贵州特色茶。16 型由人工审核的固定配置保证每款茶恰好承担两个主匹配；箭头后依次为“惊喜 / 反差”。MBTI 只改变三款茶的角色、顺序与破冰解释，不声称人格与茶存在科学对应，也不影响茶的客观资料。

三张卡使用单卡浏览，点击“先看看”只展开当前茶的破冰解释与标签，不写入 Taste Vector，也不打断冷启动流程。底部主操作固定为：

> **开始刷茶。**
> 接下来的选择，会慢慢找到你的口味。

## Journey 2：进入刷茶并校准

用户进入 Tinder 式识别 Swipe。每张卡直接显示完整立体设计图、茶名、茶类和三项性格关键词，让八款茶成为可辨认、可回访的探索对象：

- 右滑 / 点击“想喝”：正向信号；
- 左滑 / 点击“下一杯”：弱负向信号；
- Reveal 后进入详情：更强意向；
- 真喝反馈：最高权重的校准信号。

拖动时反馈与手势连续联动：右滑让 Heart 放大、填充并泛起柔光，左滑让 X 放大并增强对比；反方向图标同步退场。第二张卡从下方上移并恢复原尺寸，第三张卡补位。未过阈值整组回弹，越过阈值后顶层飞出、下层自然上位。点击 X 或 Heart 复用同一套飞卡动画；收藏保留为视觉次级按钮。

从第一次 Swipe 开始，Feed 由 Taste Vector 和必要的探索策略驱动。MBTI 冷启动不继续加权，也不参与“我开始有点懂你了”的证据说明。

## Journey 3：从喜欢进入陪伴闭环

用户刷到喜欢的茶后：

> Reveal → 茶详情 → AI 陪泡 → AI 陪品 → 风味表达 → 《雾里一芽》Tea Realm → Tea Passport

茶详情页使用服务端派生的 `TeaJourney` 展示“泡茶 → 品茶 → 茶境 → 护照”进度，并只突出一个推荐下一步。其他阶段放在弱化的“自由探索”区域，不做强制锁定。

- Brew 只有在用户显式确认“完成”阶段后才标记“已泡过”；
- Taste 只有在用户确认保存原话或提交真实品饮反馈后才标记“已品过”；
- 提前结束只结束本次陪伴，不伪造体验完成状态。

Tea Realm 是从消费体验走向文化沉浸的桥。它不要求用户先完成 Brew 或 Taste 才能进入；用户可从茶详情页随时进入。如果已有 Taste 原话，茶境在开场和收束时回扣该表达；如果没有，使用人工审核的默认文案，不伪造用户感受。

Tea-BTI 在真实行为积累后逐渐形成，不能在选择 MBTI 后立即生成。

## 特殊入口

### 场景 A：景区二维码

用户看到：

> **刷几杯，看看贵州哪杯茶会选中你。**

扫码进入 MBTI 破冰；也可以跳过后直接刷茶。

### 场景 B：茶叶包装二维码

用户扫描某款茶包装。系统已知道当前 SKU，因此跳过 MBTI 冷启动，直接进入该茶详情页：

- 泡这杯；
- 品这杯；
- 看它从哪里来。

### 场景 C：Tea-BTI / 单茶分享链接

先展示被分享的身份卡或茶卡，再通过“看看你的三杯”进入 MBTI 破冰；分享落地页不能强制注册。

# 7. 核心功能

## 7.1 MBTI 破冰｜三杯开场

### 目标

用年轻用户熟悉的身份语言制造第一次点击理由，但不让 MBTI 承担测评、诊断或长期推荐责任。

### 输入

- 固定排序的 16 型横向转盘；
- “还没测过？先凭感觉开始”；
- 用户可在“我的”中修改或删除自报类型。

### 输出

系统读取人工审核的 `mbti_seed_map`，返回三个稳定角色槽位：

| 槽位 | 前台标签 | 产品作用 |
|---|---|---|
| `mirror` | 最像你 | 用熟悉感降低第一次尝试成本 |
| `surprise` | 可能让你惊喜 | 在相邻风味中增加探索 |
| `contrast` | 和你反差但值得试 | 避免人格标签形成信息茧房 |

第一批三杯是直接显示茶名的破冰结果卡。每张卡至少显示：角色标签、茶名、一句“为什么可能合拍”的体验性解释，以及“先看看 / 继续刷”动作。

每个槽位至少包含：`tea_id`、角色和非确定性解释文案。解释文案使用“可能、也许、先试试”，不能使用“天生、注定、最适合、准确率”。

### 推荐边界

- `selected_mbti` 标记为 `self_reported`，不由系统推断；
- MBTI 不直接改变 Taste Vector 的任何维度；
- MBTI 只选择首批三杯及其顺序，不进入后续 Swipe 权重计算；
- 三杯都来自已审核的贵州茶资料与 Visual Profile；
- 三杯结果不得展示虚假匹配百分比；
- 用户跳过 MBTI 时，以一组覆盖轻盈、鲜爽、醇厚差异的探索型三杯开场。

### MVP 配置

候选茶固定为八款：都匀毛尖、湄潭翠芽、绿宝石茶、普安红、凤冈锌硒茶、遵义红、雷山银球茶、梵净山抹茶。每款茶恰好承担两个 MBTI 主匹配，三种角色顺序和解释文案必须由配置给出，不能由运行时 LLM 临场编造。未选择 MBTI 时固定返回都匀毛尖、普安红、梵净山抹茶，分别提供清鲜、温润和鲜明能量三个方向。

|---|---|
| 都匀毛尖 | ENFP → 梵净山抹茶 / 湄潭翠芽；ENTP → 梵净山抹茶 / 凤冈锌硒茶 |
| 湄潭翠芽 | INTJ → 梵净山抹茶 / 普安红；ISTJ → 绿宝石茶 / 都匀毛尖 |

### 交互与验收标准

- 新用户第一步可操作界面直接进入 MBTI；
- 中心卡突出当前类型，相邻卡部分露出，横滑吸附、点击相邻卡和左右方向键均可切换；
- 16 型顺序固定，不随机变化；下方只保留位置提示和“就选这个”；
- 用户也可以不选类型，直接开始；
- 不出现测试题、人格报告或注册阻断；
- 选择任一类型后稳定返回三张角色不同的茶卡；
- 三杯结果有明确的“继续刷”入口，最多一次点击进入 Feed；
- 更换 MBTI 可以改变角色顺序或解释，但不会清空已有 Taste Vector；
- `mbti_selected`、`mbti_skipped`、`seed_tea_opened`、`seed_batch_continue` 均可被记录；
- 后续推荐解释中不得引用 MBTI 作为证据。

## 7.2 八茶识别式探索

### 目标

让用户在直接认识茶名与茶类的前提下，根据完整立体设计图和自身当下感受探索八款茶。商品品牌、等级和价格仍不进入发现卡。

### 卡片第一态：已识别

首态显示：

1. 一张按约 9:16 完整 `contain` 的立体设计图；
2. 茶名、茶类和产区；
3. 三项性格关键词；
4. 一句感受型短标题与轻量进度。

代表特点、香气滋味、结构化冲泡建议和资料依据在详情页展开。卡片不展示内部九维向量、检测结论、商品等级或价格。

示例：

> **清一点。**  
> 像刚冒出来的嫩叶，尾巴有一点甜。  
> `轻盈` `清鲜` `回甘`

操作与反馈：

- ❤️ 想喝；
- ← 下一杯；
- ☆ 收藏（次级）；
- 左右拖动连续控制 X / Heart 强度以及下层卡片的上移和缩放；
- 按钮与拖动共用同一幂等提交和飞卡动画；
- 接口失败时卡片回位，并给出轻量重试提示。
- 长按 / 收藏（可选）。

### 卡片第二态：选择反馈

用户喜欢后给出强化反馈：

> **这一杯是：都匀毛尖**

显示：

- 茶名；
- 产区；
- 茶类；
- 专业感官标签；
- “你刚刚喜欢的感觉，在茶里通常叫……”的翻译；
- `喝这杯 →`

### 核心原则

> **先看见这杯茶，再用行为慢慢懂自己。**

### Tea Visual Grammar｜视觉风味翻译

Swipe Card 的视觉不是普通茶叶商品图，也不是给所有茶套同一种海报滤镜。它要让用户在 0.5 秒内感到这杯茶的气质，同时直接建立八款茶的视觉识别。

Feed 主卡采用用户提供的完整立体设计图：

> **一茶一幅完整立体身份图 + 统一的宣纸色页面骨架**

立体图必须 `object-fit: contain`，不得裁掉图内茶名。详情页切换为逐图配置 `object-position` 的对应实拍图；MBTI、Feed、选择反馈、推荐、护照和个人主页继续使用立体图。所有素材的来源、尺寸、哈希、权利状态和编辑链必须可追溯。

完整规则见：[Tea-BTI Tea Visual Grammar](../design/tea-visual-grammar.md)。

## 7.3 Taste Vector｜隐式味觉画像

用户每次行为产生 signal：

| 行为 | 建议权重 |
|---|---:|
| 跳过 | -0.5 |
| 喜欢 | +1 |
| 收藏 | +1.5 |
| 推荐后选择真喝 | +2 |
| 真喝后“喜欢” | +3 |
| 真喝后“不喜欢” | -3 |
| 多次主动搜索同类茶 | +1 |
| 品茶自然语言中出现明确偏好 | 动态 |

Taste Vector 可以包含：

- 鲜爽；
- 甜润；
- 醇厚；
- 涩感接受度；
- 焙火感；
- 花香倾向；
- 果香倾向；
- 清香倾向；
- 回甘；
- 尾韵长度；
- 轻盈 / 饱满；
- 清鲜 / 温熟。

第一次使用时 Vector 不稳定，推荐应保持一定探索性。

MBTI 选择不计入上述 signal。首批三杯中的点击、跳过、喜欢、Reveal、进入详情和真喝反馈按真实行为正常计权。

## 7.4 Recommendation Moment｜“我开始有点懂你了”

建议在 4–6 次 Swipe 后出现一次轻高潮。

文案：

> ### 我开始有点懂你了
>
> 你连续留下了：
> **清 / 鲜 / 有一点甜**
>
> 但两次跳过了：
> **浓 / 厚 / 尾韵特别重**
>
> **目前最想让你试：都匀毛尖**
>
> `喝这杯 →`

不使用虚假概率：

- 不显示“匹配度 92%”；
- 可以显示“当前推荐 #1”；
- 或“目前最像你的一杯”。

推荐解释只引用用户已经发生的 Swipe、收藏或品饮行为，不引用 MBTI 作为证据。例如可以说“你连续留下了清、鲜、有一点甜”，不能说“因为你是 INFP”。

# 10. Brew Mode｜AI 泡茶陪伴

## 用户问题

> 我买到了茶，但我不知道怎么泡。

## 体验目标

不是播放固定教程，而是：

> **像旁边坐着一个懂茶的人，边看边提醒。**

## 交互

用户将手机立在桌面。

摄像头可以理解：

- 是否出现茶具；
- 是否正在投茶；
- 是否注水；
- 是否出汤；
- 大致动作节奏；
- 杯 / 盖碗是否仍有茶汤。

AI 实时语音反馈：

> “这次茶叶看起来稍微多一点，可以把第一泡出得快一些。”

> “差不多可以出汤了。”

> “下一泡可以稍微延长一点。”

## 明确边界

普通摄像头无法可靠判断：

- 精确水温；
- 精确茶叶克数；
- 精确茶汤化学成分。

因此产品必须使用：

- “看起来”；
- “大约”；
- “如果你用的是 90°C 左右的水……”；

不能制造虚假精确度。

# 11. Taste Mode｜AI 品茶陪伴

## 用户问题

> 我喝到了，但不知道自己喝到了什么。

## 体验核心

让用户先用普通人的语言表达。

AI 再完成：

> **自然语言 → 茶专业语言**

示例：

用户：

> “有点像青草，但没那么冲，喝完嘴里还有一点甜。”

AI：

> “你描述的前半段比较接近嫩香 / 清鲜感，后面那点持续的甜感可以理解成回甘。”

同时记录：

- 用户原话；
- AI 翻译后的专业标签；
- 喜欢 / 不喜欢；
- 第几泡；
- 当前 Tea Taste Feedback。

该结果更新 Taste Vector。

# 12. Tea Realm｜茶境 / 《雾里一芽》

## 12.1 定位

Tea Realm 不是茶百科、文章 Feed 或风景展示页，也不是开放地图、农场经营或重游戏。

Tea Realm 是：

> **一个轻量、沉浸、可互动的“一叶成茶”体验层。**  
> 用户在刷到、泡过或喝过一杯茶的任一阶段，都可进入这杯茶背后的世界，亲手理解：  
> **“我刚刚感受到的这一口，是怎么来的？”**

它在Tea-BTI 中承担“从消费体验走向文化沉浸”的桥梁作用：将推荐、陪泡和陪品中的个人感受，连接到真实的生长环境、采摘标准、制茶工艺和人的经验。

MVP 只做都匀毛尖 Tea Realm 01：

> # 《雾里一芽》
> **雾 → 山 → 芽 → 锅 → 白毫 → 杯中这一口**

## 12.2 五项核心设计原则

1. **先做动作，再出现知识**  
   用户先拨雾、采芽、翻叶、揉捻和提毫，之后才出现对应解释，不先展示知识说明页。

2. **专业术语是体验后的压缩词**  
   不要先教“杀青、揉捻、搓团、提毫”；用户完成相应动作后，再告诉他“你刚刚这一手，叫搓团”。

3. **每个交互都要回答风味从哪里来**  
   不以“贵州很美”作为终点，而要连接环境、原料嫩度、制茶工艺、人的经验与最终的清鲜、嫩香和回甘。

4. **真实为锚，生成只做扩场**  
   真实茶园、一芽一叶、炒茶动作、干茶形态和茶汤颜色提供事实锚点；生成图像只用于风格统一、分层和非事实性装饰。

5. **70–100 秒的高密度体验**
   不追求大而全；正常用户首次完成七幕的目标时长为 70–100 秒，重点让手机真正参与制茶动作，仍适合移动端、现场试玩和路演。

## 12.3 进入规则与文案承接

Tea Realm 可从茶详情页或底部“茶境”首页随时进入，不以 Brew 或 Taste 为必修门槛。

- 如果已有用户确认保存的 Taste 原话，入场优先使用：

  > **你刚才说，它像雨后的嫩草。**  
  > **想看看这股“嫩”，是怎么走进你杯子里的吗？**

- 如果没有 Taste 原话，使用已审核的默认文案：

  > **想看看都匀毛尖的清鲜和嫩香，是怎么走进杯子里的吗？**

统一入口动作：

> `进入茶境`

点击后先出现居中分流弹窗：主路径为“通过互动，亲手走完这一芽”，此时才允许请求方向权限；次路径为“直接阅读，了解这杯茶的来路”，完整文字稿不请求方向或麦克风。文字稿按七幕组织，逐节标注事实资料、互动隐喻和体验边界。读到底并主动确认后可以领取白毫、点亮黔南；默认结果为“清鲜的白毫”，但必须标记为文字稿默认叙事结果。之后完成互动时，以行为结局覆盖默认结果。

## 12.4 《雾里一芽》七幕体验

### Scene 0｜从茶汤进入茶境

**目标**：承接茶详情或 Taste Mode，不以冷启动方式打开一个新模块。

**画面与反馈**：

- 茶汤涟漪扩散；
- 茶汤色逐渐过渡为山间雾气；
- 显示个性化或默认入场文案；
- 用户点击“进入茶境”后才请求设备方向权限或启动声音。

### Scene 1｜拨雾见山

**目标**：先进入贵州黔南都匀山地茶园的环境，而不是先读产地介绍。

**交互**：

- 支持设备方向时，用户轻轻倾斜手机移开雾层；
- 不支持、未授权或使用桌面端时，用户左右拖动雾层；
- 雾层移动后露出远山、茶园、小屋和黔南方向感。
- 雾散后出现“都匀在黔南”“高山与云雾”“一芽一叶”三个可选资料光点；不要求全部点击，下一幕始终可继续；正文与外链均从 Realm Catalog 的证据引用读取。

**动作后文案**：

> **多雾的山地，让这一片叶子慢慢长出了自己的节奏。**

### Scene 2｜摘下一芽

**目标**：让用户通过选择原料，理解都匀毛尖的嫩度要求。

**交互**：

- 茶树上同时出现独芽、一芽一叶、一芽两叶和较老叶片；
- 用户按住并上提一个芽叶，放入竹篓；
- 第一次采错时由茶师傅以半身伸手叠层给出针对性提醒；之后仍可继续观察，不出现失败、扣分或死路；
- 只保存错误类型、次数、茶师傅是否出现和最终输入方式，不保存触点路径；
- 选中一芽一叶后，显示：

  > **就是它。一芽一叶。**  
  > `1 / 53,000+`

`53,000+` 作为 MVP 记忆点直接进入 Demo 文案；它是当前已知的事实债务，正式公开发布前必须在资料目录中补齐可追溯来源。

### Scene 3｜一口锅：让它成为茶

**目标**：通过手势理解鲜叶如何逐步变成干茶，这是《雾里一芽》的核心互动。

**动作链**：

0. **散蒸汽**：吹气、手指拨开和直接开始制茶是并列选项；只有主动选择吹气才申请麦克风，只在浏览器本地判断音量变化；拒绝、不支持或超时立即提供擦拭，不阻塞后续四手；
1. **杀青**：支持方向时左右倾斜手机，让鲜叶沿锅面滑动并完成至少四次有效交替；触控降级为三次大幅向前推；
2. **揉捻**：单指横向往复，识别至少四次方向反转并限制垂直漂移；
3. **搓团**：单指画闭合圆，检查累积转角、长宽比与首尾距离；
4. **提毫**：移动端使用双指相对轻搓；多点触控不可用时改为单指短距离纵向往复。

每一步的专业名称在动作完成后出现。识别采用宽容阈值和即时指导，连续三次未识别后允许用“简化动作”继续；不设置扣分。只保存输入方式、0–100 粗粒度完成质量和尝试次数，不保存方向原始值、触点坐标或手势路径。过程中使用山风、锅内茶叶、蒸汽和叶片摩擦的轻音效，但静音不影响任何操作和信息获取。

### Scene 4｜人的经验

**目标**：让用户体会制茶判断不是一个固定倒计时。

**交互**：

- 不显示精确倒计时；
- 某一刻询问“什么时候该停？”；
- 用户点击“现在停”；
- 点击前只展示叶色、青气、白毫与火香线索，不提前显示“偏早 / 刚好 / 偏晚”；
- 偏早、刚好、偏晚三个窗口都允许完成，不给出错误标记或伪精确的唯一时点；
- 画面分别呈现鲜绿与青气、青气渐退与白毫显露、叶形收紧与火香增强。

**动作后文案**：

> **真正的手艺，没有一条固定倒计时。**  
> 茶叶的嫩度、湿度、锅温都在变。制茶人靠眼、手、鼻和经验判断。

### Scene 5｜从风格化回到真实

**目标**：用真实干茶完成体验的事实收束。

**画面与文案**：

- 锅中的风格化叶片逐渐静止；
- 镜头推近，通过渐变、遮罩或溶解过渡为真实的都匀毛尖干茶照片；
- 显示：

  > **这就是你刚刚做出来的样子。**  
  > **也是你刚才看到或喝到的那杯茶。**

- 如果有用户确认的 Taste 记录，再回扣：

  > 你说它像：  
  > **雨后的嫩草，喝完还有一点甜。**  
  > 茶语：**清鲜 · 嫩香 · 回甘**

- 没有 Taste 记录时，不生成伪用户原话，只展示审核后的都匀毛尖客观标签。

### Scene 6｜收进 Tea Passport

**目标**：以文化理解和数字标本代替金币、积分或排名奖励。

**完成结果**：

> `已解锁 · 白毫`  
> `收进 Tea Passport`

用户收集后：

- 都匀毛尖 Passport 条目标记“已解锁茶境”；
- 新增“白毫”数字标本；
- 茶境首页点亮贵州黔南区域；
- 完成记录可作为 Tea Profile 的真实经历证据；
- 不向 Taste Vector 写入感官偏好，不改变 Tea-BTI Code、Persona 或四轴。

服务端根据最近一次采芽、四手与起锅窗口生成审核过的确定性结局：`鲜青的一芽`、`清鲜的白毫` 或 `带火香的一芽`。结局默认私有，只进入完成页、茶境首页和 Tea Passport，并始终显示“这是互动体验结果，不代表真实加工批次或专业制茶能力评价。”

茶境首页的核心文案：

> **喝过的茶，会慢慢长成你的世界。**

## 12.5 设备能力与无障碍降级

- `DeviceOrientationEvent` 只能在用户点击“进入茶境”后请求；
- 设备方向是增强能力，不是通关依赖；
- iOS 拒绝授权、浏览器不支持或桌面端访问时，所有倾斜交互自动换为拖拽 / 指针交互；
- 支持 `prefers-reduced-motion`，用渐变和静态状态替代强视差、粒子和溶解动画；
- 提供“跳过动画”、“静音”和“重新体验”；
- 不请求摄像头；麦克风只在用户点击“吹开蒸汽”后可选请求，浏览器只检测本地音量变化，不录音、不上传、不保存原始音频；
- 屏幕手势和设备方向只用于当前互动，不声称识别真实锅温、茶叶质量、现实制茶动作或专业制茶能力。

## 12.6 视觉资产与事实边界

### 必须使用真实锚点

- 都匀茶山 / 茶园空间参考；
- 都匀毛尖一芽一叶形态；
- 真实手工炒茶照片或视频，用于锅、手、叶和蒸汽的动作参考；
- 都匀毛尖干茶微距照片；
- 都匀毛尖茶汤照片与颜色基准。

### 可以使用图像生成补足

- 风格化茶山主场景和氛围帧；
- 透明背景雾层、远山层和前景叶片；
- 炒茶作坊背景、小屋和非事实性装饰；
- Tea Passport 收集卡和“白毫”标本卡的风格层。

生成资产不得单独承担芽叶形态、茶汤色、制茶动作或产地地貌的事实证明。所有资产必须记录来源、真实性状态、使用权、事实依据和在 Tea Realm 中的用途，并与同一款茶的 Visual Profile 继承关系保持一致。

## 12.7 状态与后续契约要求

PRD 定义以下业务状态，本轮不直接规定公共 API 路径：

- `realmId`：《雾里一芽》的稳定标识；
- `teaId`：与都匀毛尖茶资料和 Visual Profile 共用的茶品 ID；
- `currentScene`：当前幕；
- `completedScenes`：已完成幕列表；
- `interactionMode`：`orientation` / `pointer` / `reducedMotion`；
- `completedAt`：首次完成时间；
- `specimenId`：已解锁的“白毫”数字标本；
- `passportCollected`：是否已收进 Tea Passport。
- `runState`：最近一次体验的 `runId`、是否重玩、当前幕、已完成幕、白名单行为摘要与耗时；
- `latestOutcome`：最近一次完整体验由服务端模板生成的私有结局。

中途刷新或重新打开时，从最后完成的 Scene 继续；用户可主动选择“重新体验”。完成写入必须幂等，重复提交不能重复创建标本、重复点亮地图或重复更新 Profile 证据。

Realm Definition、Progress 和 Completion 契约以 OpenAPI 快照为准；客户端必须提交当前 `runId`，但不得直接提交结局文案。

## 12.8 埋点要求

MVP 至少记录：

- `realm_preview_opened`；
- `realm_started`；
- `realm_scene_completed`，附带 `sceneId` 和所用时长；
- `realm_interaction_fallback_used`，附带降级原因和 `interactionMode`；
- `realm_real_asset_revealed`；
- `realm_specimen_collected`；
- `realm_completed`，附带总时长、完成方式和是否使用 Taste 原话。

埋点不得包含未经用户确认公开的完整品饮原话。

## 12.9 MVP 验收标准

1. 有 Taste 原话和无 Taste 原话两种入口都能完成七幕流程；
2. iOS 设备方向授权、拒绝授权、无传感器设备和桌面拖拽都可通关；
3. 一芽选择错误时只给温和提示，不出现扣分或死路；
4. 正常操作的首次体验总时长控制在 70–100 秒；
5. 390px 移动视口不出现内容溢出、必要按钮遮挡或交互死区；
6. 风格化画面必须过渡到经审核的真实干茶照片，生成资产不得承担茶形、茶汤或工艺事实；
7. 重复完成不会重复创建 Passport 标本，也不会错误更新 Taste Vector 或 Tea-BTI；
8. 全流程不请求摄像头；麦克风仅在用户主动吹气时用于本地音量阈值检测，并可完整降级；不声称识别现实世界的叶片、锅温、茶叶质量或专业能力。

### 14.3.1 茶桌精神速写详情

`/profile/tea-bti` 的内容节奏固定为：**人格暴击 → 茶桌习惯 → 你以为 / 实际上 → 茶桌小剧场 → 茶桌天敌 → 名场面与千万别说 → 固定 CP → 这不是结论 → 四轴与真实证据 → 继续变化**。语气只调侃喝茶行为，不攻击用户，不贬低任何茶类，也不使用伪科学、匹配百分比或诊断措辞。

16 型各自拥有人工审核的一句话暴击、5 条习惯、4 组反差、3 个小剧场、3 个场景型“茶桌天敌”、名场面、千万别说和一个固定 CP。固定互配为：`FLSE ↔ MRTC`、`FLSC ↔ MRTE`、`FLTE ↔ MRSC`、`FLTC ↔ MRSE`、`FRSE ↔ MLTC`、`FRSC ↔ MLTE`、`FRTE ↔ MLSC`、`FRTC ↔ MLSE`。CP 只提供关系梗和对话，不提供匹配分、好友查询或茶叶推荐。

详情页前半段允许轻松表达，后半段必须回到“这只是最近喝出来的样子”。真实证据最多三条，只能来自已存在的品饮原话、喜欢、收藏和跳过事件，不生成次数、停留时长或未发生的行为。形成中只显示待形成状态、已有线索和明确行动条件，不猜测临时人格。

页面顶部复用 Tea Profile 分享 Sheet；分享的仍是当前公开 Profile，不生成长图，也不把详情页新增行为证据带入公开接口。

## 14.4 形成条件与状态

推荐算法继续使用连续 Taste Vector；Tea-BTI 只是面向用户的可解释身份层。

MBTI 冷启动与 Tea-BTI 必须使用不同字段、不同更新时间和不同界面文案：

- `selected_mbti`：用户自报，可为空、可修改、可删除；
- `taste_vector`：由行为持续更新，是推荐依据；
- `tea_bti_code`：由 Taste Vector 与探索行为计算；
- `tea_bti_persona`：Code 对应的人工审核人格名与解释；
- `profile_blocks`：由用户记录和真实行为更新的展示组件。

Demo 至少积累 5 次 Swipe，并包含 1 次喜欢、收藏或真实品饮后，才显示 Tea-BTI“初见”；此前只显示“正在形成”。形成中同时返回已完成选择、剩余选择和正向信号是否完成，界面不得遗漏其中任一条件。

Tea Realm 完成记录只能作为 Tea Profile 中的文化探索证据或 Passport 收集记录，不作为感官偏好信号，不写入 Taste Vector，也不直接改变 Tea-BTI 四轴。

Tea-BTI 状态：

- 正在形成；
- 初见；
- 逐渐稳定；
- 最近发生变化。

避免一次生成、永久固定。Code 或 Persona 发生变化时，应解释“最近哪些选择让它改变”，而不是突然替换身份。

## 14.5 Block｜可编辑、可展示、可生长

Tea Profile 由可独立更新的 Block 组成，而不是一张生成后失去数据关系的固定 PNG 海报。

首批 Block：

| Block | 内容 | 数据来源 | 用户控制 |
|---|---|---|---|
| `IDENTITY` | Persona Name、Code、简介、核心标签 | Tea-BTI + 用户简介 | 可编辑简介、不可伪造行为数据 |
| `MY_TEA` | 本命茶与形成理由 | 喜欢、复饮、收藏、真喝反馈 | 可隐藏、可手动选择候选中的一杯 |
| `CURRENTLY_DRINKING` | 最近在喝、第几泡 | Brew / Taste Session | 可隐藏 |
| `MY_WORDS` | 用户自己的品茶原话 | Taste Session 原始记录 | 可挑选、编辑公开版本 |
| `TEA_MAP` | 已喝茶品对应的贵州产区 | Tea Passport | 可隐藏，不展示实时位置 |
| `TEA_PASSPORT` | 探索进度与已解锁茶 | Tea Passport | 可隐藏 |
| `MOOD` | 最近偏爱的风味与场景 | 近期 Taste Vector | 可隐藏，明确标记“最近” |
| `STATS` | 已刷、已喝、已收藏数量 | 行为日志 | 可隐藏 |

后端继续以 `IDENTITY / MY_TEA / MY_WORDS / TEA_PASSPORT` 四个 Block 聚合和控制分享范围，不做拖拽排序。私有浏览页不把这些内部 Block 直接渲染为四张管理卡，而是组合为一个身份与三条证据；分享 Sheet 和 `/profile/edit` 使用消费者文案“Tea-BTI 身份 / 本命茶 / 我说过 / 茶护照”。系统只自动更新内容，不擅自公开私密记录。

- 删除分享链接后，公开 Profile 应立即不可访问。

未来可探索：

# 16. 信息架构

MBTI 选择与第一批三杯属于进入 Feed 前的破冰流程，不占用底部一级 Tab。用户完成或跳过后进入“刷茶”，以后可从“我的”修改自报 MBTI，但不会重置 Taste Vector。

茶详情、Brew、Taste 和 Tea Realm 是单茶纵向体验，沉浸页不显示底部导航。Passport 完成单杯记忆收束后，主操作进入“我的 Tea-BTI”，再以“继续刷下一杯”回到留存循环。

导航遵循“主路径可回退、茶境可回看”的约定：三杯破冰第二步可返回 MBTI，Reveal、Recommendation 和茶详情必须提供可见返回入口；茶详情通过允许列表来源返回刷茶、茶护照或“喝出来的我”，从刷茶返回时恢复到刚才的下一张卡。Brew、Taste 与 Tea Realm 继续携带该来源，不依赖浏览器历史猜测落点。

Tea Realm 始终保留独立退出，并从第二幕开始提供“上一幕”。上一幕只回看已经走过的场景，不撤销 `completedScenes`、数字标本、Passport 或用户已经提交的任何行为；回看后再次向前只在客户端经过已完成场景，抵达服务端当前幕时才继续写进度。从茶详情进入时退出回该茶详情，从底部“茶境”进入时退出回茶境首页。

底部只保留三个一级 Tab：

## 1. 刷茶

- 八茶识别式 Swipe；
- Reveal；
- Recommendation Moment。

## 2. 茶境

- 核心文案：“喝过的茶，会慢慢长成你的世界。”；
- 都匀毛尖《雾里一芽》入口；
- 已解锁的茶境章节与数字标本；
- 黔南区域点亮状态；
- 完整贵州茶地图与多茶境留到后续扩展；地图方向采用“九市州地理底板 + 茶脉路线 + 个人茶足迹”，详见 [`guizhou-tea-map.md`](guizhou-tea-map.md)。

- Tea Passport；
- Tea-BTI / 我的茶名片；
- Profile Block 编辑与分享；
- 收藏；
- 品饮历史。

“泡这杯 / 品这杯”属于单茶详情页。

“AI 茶伴”是浮动 Companion，不是一级 Tab。

# 20. 产品原则

1. **零问卷、低摩擦冷启动**  
   MBTI 只允许直接选择或跳过；能从后续行为获得的信息，不在开始前追问。

2. **先感觉，后术语**  
   用户先说“像青草”，再告诉他可能叫“嫩香”。

3. **AI 尽量藏在体验后面**  
   不把“AI 茶艺师 Chatbot”作为产品首页。

4. **不给伪科学披 AI 外衣**  
   不制造虚假精度和不可靠判断。

5. **文化必须可体验，不只是可阅读**  
   Tea Realm 优先于资讯流；先让用户拨雾、采芽和制茶，再告诉他动作背后的术语与事实。

6. **MBTI 是入口，Tea-BTI 是结果**  
   MBTI 只负责破冰；Tea-BTI 由行为形成，二者不能互相冒充。

7. **现实的一杯茶是最终验证**  
   推荐不是结束，喝完以后才有校准。

8. **视觉是风味翻译，不是风格装饰**  
   真实茶提供可信锚点，结构色、抽象形和环境暗示必须有依据。

9. **视觉身份逐步 Reveal**  
   Feed 直接建立茶名与立体图的识别，选择反馈、实拍详情与 Tea Realm 延续同一 Visual Profile。

10. **Profile 是数据视图，不是一次性海报**  
    Block 来自真实行为并允许用户控制公开范围；分享图片只是当前公开 Profile 的快照。

11. **分享必须把人带回体验**  
    分享落点是可浏览的公开 Tea Profile，下一步才是好友自己的三杯破冰。

# 21. 产品核心文案候选

首屏传播 Hook：

> **你的 MBTI，会喝什么茶？**  
> 先从三杯开始。

> **开始刷茶。**
> 留下想喝的，划走没感觉的。

> **MBTI 负责破冰，刷茶负责懂你。**

Demo Storytelling 主线：

> **你先告诉茶你是谁，茶再慢慢告诉你，你喜欢什么。**

阶段叙事：

> **MBTI：认识你 → 刷茶：理解你 → Tea-BTI：成为你**

长期身份表达：

> **从 MBTI 开始，以 Tea-BTI 认识自己。**

主 Slogan：

> **你不用先懂茶。刷几下，茶先开始懂你。**

> **别教年轻人怎么喝茶。先让他刷到第一杯想喝的茶。**

长期品牌表达：

> **刷茶，不只是帮你找到第一杯。它陪你把第一杯，慢慢喝成自己的茶。**

Tea-BTI：

> **一杯一杯，喝出自己的茶味。**

长期体验：

> **茶越来越懂你，你也越来越懂自己。**
